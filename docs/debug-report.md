### Ошибка 1: Ошибка компиляции заголовочного файла `<windows.h>` на Linux
* **Тип:** Ошибка времени компиляции (Синтаксическая / Платформозависимая)
* **Где:** `src/main.cpp`, строки 2, 10-11
* **Симптом:** Компилятор GCC в Linux выдавал критическую ошибку `fatal error: windows.h: No such file or directory`.
* **Причина:** Использование Windows API (`SetConsoleOutputCP`) для UTF-8, неприменимого в средах POSIX/Linux.
* **Решение:** Удален заголовок `<windows.h>`. Консоль Linux нативно поддерживает кодировку UTF-8.
* **Статус:** Исправлено
* **Коммит:** `0c1d2f2`

### Ошибка 2: Отсутствие обработки исключения при делении на ноль
* **Тип:** Ошибка времени выполнения (Runtime Error / Exception)
* **Где:** `src/core/evaluator.cpp`, метод `evaluate()`
* **Симптом:** При передаче выражений вида `5/0` программа выдавала неопределенное значение `inf` без объяснения шагов.
* **Причина:** Отсутствие валидации операторов деления перед генерацией шагов решения.
* **Решение:** Добавлена проверка строк на наличие паттернов `/0` и `:0` с генерированием исключения `std::runtime_error`.
* **Статус:** Исправлено
* **Коммит:** `a05fb15`

### Ошибка 3: Отсутствие условного отладочного вывода состояния
* **Тип:** Логическая ошибка / Отсутствие режима отладки
* **Где:** `src/main.cpp`
* **Симптом:** Сложно отслеживать промежуточные этапы нормализации строк без замусоривания продакшн-вывода.
* **Причина:** Отсутствие механизмов условной компиляции.
* **Решение:** Внедрен макрос `#define DEBUG_MODE` для условного вывода диагностических логов `#if DEBUG_MODE`.
* **Статус:** Исправлено
* **Коммит:** `4ef4127`
