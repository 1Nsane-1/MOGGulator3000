# Чек-лист инспекции кода MOGGulator3000

## Дата: 02.10.2026
## Проект: MOGGulator3000 (C++17 / CMake)
## Инспектор: Грузин Егор

## 1. Именование
- [ ] Локальные переменные и параметры функций в `camelCase`.
- [ ] Имена функций и методов в `camelCase`.
- [ ] Классы и структуры в `PascalCase`.
- [ ] Константы и перечисления (`enum`) в `UPPER_SNAKE_CASE`.
- [ ] Приватные поля классов имеют префикс `m_` (например, `m_expression`).
- [ ] Файлы исходного кода в `snake_case` или `kebab-case`.
- [ ] Имена осмысленные (отсутствуют `a`, `b`, `tmp_x`).

## 2. Структура кода и оформление
- [ ] Отступы — ровно 4 пробела (единообразно по всему проекту).
- [ ] Длина строки не превышает 120 символов.
- [ ] Длина функции не превышает 50 строк.
- [ ] Вложенность блоков не превышает 3 уровней.
- [ ] Отсутствует дублирование кода (DRY).

## 3. Комментарии и документация
- [ ] Публичные методы классов задокументированы в стиле Doxygen (`///`).
- [ ] Сложные алгоритмы (парсинг выражений, приоритеты) прокомментированы.
- [ ] В коде нет закомментированных неиспользуемых участков.

## 4. Константы и «магические числа»
- [ ] Отсутствуют «магические числа» (например, `1e-6`, `100`, статусы без имени).
- [ ] Все константы вынесены в `constexpr` или `const` со строгой типизацией.

## 5. Обработка ошибок и исключения
- [ ] Используются пользовательские исключения, унаследованные от `MoggException`.
- [ ] Нет пустых блоков `catch(...)`.
- [ ] Исключения содержат информативные сообщения об ошибке.

## 6. Модульность и C++ специфика
- [ ] Соблюдается принцип единственной ответственности (SRP).
- [ ] Передача тяжелых объектов по `const &`.
- [ ] Используется `nullptr` вместо `0` или `NULL`.
- [ ] Отсутствуют циклические зависимости в заголовочных файлах (используется `#pragma once`).

## 7. Сборка и Git
- [ ] Проект успешно собирается через CMake без предупреждений компилятора (`-Wall -Wextra`).
- [ ] Файлы сборки (`build/`, `.vs/`) внесены в `.gitignore`.
- [ ] Сообщения коммитов оформлены по стандарту Conventional Commits.
