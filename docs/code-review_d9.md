# Ревью документации и результатов тестирования (День 9)

**Проверяемая команда:** Команда №2 (Проект ParkBooking)
**Ревьюер:** 1Nsane-1 (Грузин Егор)

## Комментарии и замечания по тестированию

1. **Отсутствие шагов воспроизведения в BR-02 (Критическое):**
   В баг-репорте BR-02 («Ошибка расчета стоимости при ночной аренде») указаны только ожидаемый и фактический результаты, но отсутствуют шаги воспроизведения (не указаны входные данные, объект и временной интервал). Необходимо добавить пошаговый сценарий воспроизведения.

2. **Неполная трассировка тест-кейсов в протоколе:**
   В `docs/test-protocols.md` для падающих тест-кейсов со статусом `❌ Не пройден` не добавлены ссылки на созданные баг-репорты. Рекомендуется явно указывать айди бага в комментариях к статусу (например, `см. BR-01`).

3. **Недостаточный охват нефункциональных сценариев в чек-листе:**
   В чек-листе отсутствуют проверки поведения системы при сетевых сбоях и при вводе некорректных форматов дат (например, прошедшая дата или несуществующее 31 февраля). Стоит внести эти проверки в раздел «Обработка ошибок».

4. **Отсутствие точных метрик в нефункциональных тестах:**
   В протоколе для TC-12 (Скорость загрузки карты) указан только статус `✅ Пройден`, без фиксации времени отклика в секундах. Фиксация числовых показателей (например, `1.2 сек`) необходима для сравнения при повторных прогонах.
